# Personal Site Project

## Purpose

`personal-site` is the canonical workspace for Sebastian's long-term public-facing personal presence and body of work. The website is one surface of the project, not the whole project.

The project may include:

- the personal website and its content;
- GitHub profile/presence and related presentation;
- essays, articles, notes, and published writing;
- ideas, experiments, projects, and selected work;
- durable material that may later be republished across other public surfaces.

## Current direction

Build a coherent personal corpus that can grow over time without forcing every idea into a website feature. Keep the underlying source material durable and reusable, then decide later where each piece should appear.

The current website implementation is an Astro static site. Preserve the existing implementation and content conventions unless a future spec explicitly changes them.

## Goals

1. Give future agents a durable, canonical understanding of what this project is.
2. Make it easy to add new writing, ideas, projects, and public surfaces without losing context.
3. Keep the website, GitHub presence, writing, and future outputs conceptually connected.
4. Preserve the author's voice and decisions rather than normalizing them into generic marketing copy.
5. Keep work resumable across ChatGPT/agent sessions through repository-backed state.

## Non-goals

- This repository is not a raw chat transcript archive.
- It is not a dumping ground for credentials, private infrastructure details, identifiable client information, or other secrets.
- It is not assumed that every stored idea must become a public webpage.
- Do not redesign or re-platform the site merely as part of project initialization.

## Lifecycle

Current state: `DISCOVERY`.

Stay in discovery until there is a concrete next objective. When a direction becomes sufficiently clear, capture it as a spec or ADR before non-trivial implementation.

## Privacy boundary

Until repository visibility is explicitly verified as private, only public-safe project metadata and non-sensitive context may be persisted here. Existing privacy red lines in `AGENTS.md` remain authoritative.
